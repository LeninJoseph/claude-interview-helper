## How to use this handbook

1. **Read a page end to end**, run every code block (copy button top-right of each block).
2. **Close the page and answer its Q&A bank out loud** — interviews are spoken, not written.
3. **Revisit weak areas**; the cheatsheet is for the final 24 hours.

## Suggested 4-week plan

| Week | Focus | Pages |
|---|---|---|
| 1 | Python depth | Fundamentals → Functions → OOP → Advanced → Internals → Concurrency |
| 2 | Backend | REST → Frameworks → Security → SQL → DB internals → NoSQL/ORM |
| 3 | Design | SOLID → Patterns → Data modeling → System design |
| 4 | DSA + mock | Complexity → Data structures → Algorithms → Patterns (2 problems/day) + Q&A banks |

!!! tip "How senior interviews are scored"
    Interviewers look for **trade-offs**, not definitions. For every concept, be ready to answer:
    *What problem does it solve? What does it cost? When would you NOT use it?*
    Each page has a **"Say this in the interview"** box with a crisp, senior-level answer.
